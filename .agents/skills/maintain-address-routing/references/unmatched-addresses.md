# Диагностика нераспределённых адресов

## Выходные файлы

| Файл | Что означает |
| --- | --- |
| `Не распределено.xlsx` | Сводка нераспределённых домов. |
| `Не распределено_подробно.xlsx` | Адрес, исходный PDF и подробности для воспроизведения. |
| `Не удалось разобрать адреса.txt` | Адрес найден в тексте, но его структура не разобрана. |
| `Не найден адрес в PDF.txt` | На странице не найден кандидат адреса; содержит PDF, страницу и фрагмент текста. |

## Где исправлять

| Симптом | Основной код | Тесты |
| --- | --- | --- |
| Адрес не найден в тексте PDF | `org.vc.address.AddressExtractor` | `AddressExtractorTest` |
| Неверно выделены улица, дом, буква или корпус | `PaymentAddressParts`, `AddressParts`, `AddressParser` | `PaymentAddressPartsTest`, `AddressParserTest` |
| Неизвестное сокращение или тип улицы | `AddressPatterns`, `StreetTypeNormalizer` | `AddressParserTest` |
| Разные записи одного адреса дают разные ключи | `AddressKeyNormalizer`, `AddressCleaner` | `AddressNormalizerTest` |
| Адрес разобран, но выбран неверный курьер | `CourierAddressKey`, `CourierMatcher` | `CourierMatcherTest` |
| Excel прочитан неверно | `CourierExcelReader` | `CourierExcelReaderTest` |
| Неверный состав диагностического отчёта | `UnmatchedAddressRegistry`, `UnmatchedAddressExcelWriter` | `UnmatchedAddressRegistryTest` |
| Неверный порядок общего сценария | `CourierPaymentService` | сервисные и интеграционные проверки |

## Безопасный порядок fallback

1. Точный адрес в том же населённом пункте.
2. Канонический адрес с нормализованным названием улицы.
3. Адрес без неоднозначного корпуса.
4. Однозначный маршрут улицы в том же городе.
5. Однозначное сокращённое или близкое название улицы.
6. Однозначный связанный адрес той же платёжки.
7. Для режима обязательного распределения: тот же адрес на других страницах PDF, затем ближайшая подтверждённая страница, затем доминирующий маршрут исходного файла.
8. Оставлять запись в отчёте только если во всём PDF не найден ни один подтверждённый курьер.
