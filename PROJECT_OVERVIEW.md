# Устройство проекта payment-courier-tool

Приложение распределяет страницы готовых PDF-платёжек по папкам курьеров. Маршруты загружаются из Excel, адреса извлекаются из текста PDF, нормализуются и сопоставляются без учёта квартиры.

Генерация новых платёжных форм из XML удалена: проект отвечает только за подготовку маршрутов, сортировку готовых PDF и отчётность.

## Поток обработки

1. `ParserPresenter` при необходимости обновляет адреса курьеров из выбранного Excel.
2. `CourierPaymentService` читает маршруты и настраивает `CourierMatcher`.
3. Исходные PDF открываются с дисковым scratch-кэшем PDFBox. По умолчанию одновременно обрабатываются два файла.
4. `AddressExtractor` извлекает адреса каждой платёжки, а `CourierMatcher` ищет курьера по нормализованному адресу дома.
5. Если прямого совпадения нет, `PdfFileRoutingContext` проверяет подтверждённый такой же адрес, ближайшую страницу и доминирующий маршрут исходного PDF.
6. `PdfPageTempStorage` сохраняет назначенные страницы во временные одностраничные PDF.
7. `CourierPdfWriter` сортирует страницы и последовательно собирает части не более чем по 5000 страниц.
8. После успешной записи каждой части временные страницы сразу удаляются.
9. `CourierReportWriter` и классы отчётности создают сводку, реестр и диагностику нераспределённых адресов.

## Ограничения памяти и производительность

- Исходные PDF используют смешанный кэш с лимитом 64 МБ на файл, после чего данные сбрасываются на диск; объединяемые PDF используют `MemoryUsageSetting.setupTempFileOnly()`.
- Количество параллельно читаемых PDF задаётся свойством `paymentCourier.pdfThreads`; безопасное значение по умолчанию — `2`.
- Итоговые PDF собираются строго последовательно: параллельный merge нескольких крупных документов создаёт опасный пик памяти.
- Один выходной файл содержит не более 5000 физических страниц; настройка — `paymentCourier.maxPagesPerFile`.
- UI хранит не более 200 000 последних символов лога и обновляет окно пакетно, а не отдельной Swing-задачей на каждую строку.
- Release-конфигурация использует `-XX:MaxRAMPercentage=50.0`, поэтому на машине с 12 ГБ heap ограничен примерно шестью гигабайтами.
- Для скорости важен свободный SSD: временный scratch-кэш сознательно обменивает дополнительный дисковый ввод-вывод на стабильность памяти.

## UI и MVP

- `ParserFrame` — Swing-представление.
- `ParserView` — контракт представления.
- `ParserPresenter` — пользовательские сценарии и проверка выбранных путей.
- `ParserTaskRunner` — фоновый запуск и защита от повторного старта.

## Диагностические файлы

В папке `Документы/Курьеры` формируются:

- `Итог сортировки.xlsx`;
- `Реестр адресов.xlsx`;
- `Не распределено.xlsx`;
- `Не распределено_подробно.xlsx`;
- `Не удалось разобрать адреса.txt`;
- `Не найден адрес в PDF.txt`.

## Проверка изменений

Минимальная проверка кода:

```cmd
mvn test
mvn -DskipTests package
```

Перед выдачей EXE и ZIP использовать `.agents/skills/build-desktop-release` и его `scripts/build-release.ps1`.

## Правила доработок

- Новое правило адреса закреплять тестом на реальном формате.
- Сортировать по первому адресу платёжки, но оба адреса сохранять в реестре.
- Не использовать адрес поставщика вместо адреса помещения.
- Не увеличивать параллельность чтения или записи без замера пикового heap на больших PDF.
- Не выполнять Git push.
