# Правила работы с проектом

## Проектные skills

Перед изменением кода выбрать и прочитать подходящий skill из `.agents/skills`:

- `maintain-address-routing` — извлечение, разбор и сопоставление адресов, Excel-маршруты и отчёты о нераспределённых платёжках;
- `build-desktop-release` — тестирование, сборка JAR, EXE и ZIP.

Если изменение добавляет устойчивое правило, новый диагностический путь, обязательную проверку или меняет команду сборки, обновить соответствующий skill в той же задаче. Не записывать в skills разовые данные конкретного документа.

## Общие ограничения

- Не выполнять Git push. Commit делать только по прямой просьбе пользователя.
- Комментарии, JavaDoc, пользовательские сообщения и проектная документация должны быть на русском языке.
- Не добавлять JavaDoc, который только повторяет имя метода, параметра или возвращаемого значения.
- Сначала прослеживать фактический путь данных, затем исправлять самый ранний неверный слой.
- Каждое новое правило разбора адреса или структуры платёжки закреплять тестом на реальном формате.
- Перед выдачей сборки запускать весь `mvn test` и использовать skill `build-desktop-release`.

Общую архитектуру и потоки данных смотреть в `PROJECT_OVERVIEW.md`.
