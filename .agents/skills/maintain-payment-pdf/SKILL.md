# Платёжки XML → PDF

## Прослеживать весь конвейер

1. Проверить поля исходного XML в `XmlPaymentDocumentParser`.
2. Проверить, что данные без потерь попали в модели `org.vc.payment`.
3. Проверить подготовку сценария в `XmlPaymentPdfGenerationService`.
4. Исправлять разметку через `HtmlPaymentDocumentRenderer` и шаблоны в `src/main/resources/templates/payment`.
5. Использовать ручную PDFBox-вёрстку только как резерв для сравнения, не развивать две реализации параллельно.

## Сохранять инварианты

- Не придумывать отсутствующие значения и не подменять пропуски чужими полями.
- Сохранять порядок блоков и таблиц эталонной платёжки.
- Формировать оба QR-кода из соответствующих XML-данных; QR должен открываться банковским приложением.
- Не допускать наложения текста, обрезания заголовков и разрыва одной таблицы между страницами.
- Сначала уплотнять отступы и высоты строк, затем умеренно уменьшать шрифт и QR.
- По возможности удерживать платёжку на одном листе, сохраняя читаемость.
- Сначала использовать адрес помещения, затем адрес доставки.

Подробную визуальную проверку выполнять по [references/layout-checklist.md](references/layout-checklist.md).

## Проверять изменение

- Добавить или обновить тест XML-парсера для нового поля.
- Добавить тест renderer/writer для структуры документа.
- Сгенерировать минимум два PDF: обычный и максимально заполненный.
- Визуально сравнить страницы с эталоном после рендера в изображение.
- Отдельно проверить оба QR-кода.
- Запустить весь `mvn test`.

## Поддерживать skill

Обновлять skill при изменении источника данных, порядка блоков, алгоритма QR, стратегии уплотнения или основной реализации renderer. Значения конкретной платёжки в skill не сохранять.
