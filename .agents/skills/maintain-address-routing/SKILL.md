# Маршрутизация адресов

## Начинать с фактического пути данных

1. Взять запись из `Не распределено_подробно.xlsx`, `Не удалось разобрать адреса.txt` или `Не найден адрес в PDF.txt`.
2. Проверить исходный текст конкретной страницы PDF.
3. Проверить исходную строку того же адреса в Excel маршрутов.
4. Определить слой ошибки: извлечение, разбор, нормализация, сопоставление или отчёт.
5. Исправлять самый ранний неверный слой, не добавлять адрес в список исключений без необходимости.

Карту файлов и диагностических отчётов читать в [references/unmatched-addresses.md](references/unmatched-addresses.md).

## Сохранять правила распределения

- Сортировать по первому адресу платёжки; оба адреса сохранять в реестре.
- Сначала искать `Адрес помещения:`, затем допустимый запасной адрес.
- Не принимать адрес поставщика и банковские реквизиты за адрес помещения.
- Сопоставлять дом без квартиры, но учитывать населённый пункт, номер, букву и корпус.
- Не выбирать первого курьера при обычном сопоставлении. После исчерпания точных fallback допустим принудительный контекст исходного PDF: тот же адрес, ближайшие подтверждённые страницы, затем доминирующий маршрут файла.
- Связанный адрес той же платёжки использовать только при единственном подтверждённом курьере.
- Общую нормализацию предпочитать логике для конкретного поставщика. Формат поставщика выделять только на уровне извлечения текста.

## Проверять изменение

- Добавить минимальный unit-тест с реальной формой проблемного адреса.
- Для неоднозначного адреса добавить отрицательный тест или пример другого города.
- Запустить адресные тесты, затем весь `mvn test`.
- На больших данных проверить количество платёжек до и после распределения и наличие диагностических файлов.

## Сохранять предсказуемое потребление памяти

- Исходные PDF открывать через ограниченный `MemoryUsageSetting.setupMixed(...)`; текущий лимит — 64 МБ на одновременно открытый файл.
- По умолчанию обрабатывать не более двух PDF одновременно; настройка — `paymentCourier.pdfThreads`.
- Итоговые PDF курьеров собирать последовательно и удалять временные страницы сразу после успешной записи части.
- Сохранять ограничение 5000 страниц на один выходной PDF.
- Не убирать лимит истории и пакетное обновление `LogOutputStream`: подробный лог большого запуска не должен становиться отдельной причиной OOM.

## Поддерживать skill

Обновлять этот skill и reference, если появился новый слой адресной обработки, новый отчёт, устойчивое правило сопоставления или изменился порядок fallback. Разовые адреса сюда не записывать.
